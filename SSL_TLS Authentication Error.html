Your log shows a Kafka client failing to authenticate over SSL/TLS, and the key error is:

SSL handshake failed
PKIX path building failed
unable to find valid certification path to requested target

What this actually means

Your Java client (Kafka producer/consumer) does not trust the server’s SSL certificate. During the TLS handshake, Java tries to validate the broker’s certificate chain and fails.

Root cause (most likely)

The JVM cannot find a trusted certificate chain from the broker’s certificate to a trusted root CA.

In plain terms:

  • Kafka broker presents a certificate

  • Your client checks it against its truststore

  • The certificate (or its CA) is missing from the truststore

Clues from your log

  • org.apache.kafka.common.errors.SslAuthenticationException

  • SunCertPathBuilderException

  • X509TrustManagerImpl.checkServerTrusted

These specifically point to certificate validation failure, not network or credentials.

Common reasons this happens

1. Missing CA certificate in truststore

Your client doesn’t have the CA that signed the Kafka broker cert.

2. Self-signed certificate

If Kafka uses a self-signed cert, Java will reject it unless explicitly trusted.

3. Wrong truststore configured

Your app might be pointing to:

  • wrong file

  • empty truststore

  • wrong password

4. Certificate chain incomplete on server

Kafka broker may not be sending full chain (intermediate cert missing).

5. Hostname mismatch (less likely here)

Would usually show hostname verification failed, but worth checking.

How to fix it

✅ Step 1: Verify your client SSL config

Check your Kafka properties:

properties
security.protocol=SSL
ssl.truststore.location=/path/to/truststore.jks
ssl.truststore.password=*****

✅ Step 2: Add broker certificate (or CA) to truststore

If you have the broker cert:

Bash
keytool -import -alias kafka-broker \
  -file broker.crt \
  -keystore truststore.jks

✅ Step 3: Validate certificate chain

From your machine:

Bash
openssl s_client -connect <broker-host>:9093 -showcerts

Check:

  • Full chain is returned

  • No missing intermediate certs

✅ Step 4: If using self-signed cert

You must import it manually into the truststore (Java won’t trust it otherwise).

✅ Step 5: Debug with JVM SSL logs

Run with:

Bash
-Djavax.net.debug=ssl,handshake

This will show exactly which cert is rejected.

Quick diagnosis shortcut

If you're unsure, try:

  • Does it work with ssl.endpoint.identification.algorithm= (empty)?

  • Does it work if you temporarily use a trust-all config? (only for testing)

If yes → definitely truststore issue.

Bottom line

👉 Your Kafka client cannot validate the broker’s SSL certificate.
👉 Fix = correct truststore with proper CA/cert chain.

  • ou ton fichier peut devenir incompatible

5. 🐛 Bugs difficiles à diagnostiquer

🧩 Implémentation

Java
// Truststore custom
KeyStore customKs = KeyStore.getInstance("JKS");
customKs.load(new FileInputStream("truststore.jks"), "password".toCharArray());

TrustManagerFactory customTmf =
    TrustManagerFactory.getInstance(TrustManagerFactory.getDefaultAlgorithm());
customTmf.init(customKs);

// Truststore par défaut (cacerts)
TrustManagerFactory defaultTmf =
    TrustManagerFactory.getInstance(TrustManagerFactory.getDefaultAlgorithm());
defaultTmf.init((KeyStore) null);

🔹 Étape 2 — Créer un TrustManager combiné

Java
X509TrustManager customTm = (X509TrustManager) customTmf.getTrustManagers()[0];
X509TrustManager defaultTm = (X509TrustManager) defaultTmf.getTrustManagers()[0];

X509TrustManager combinedTm = new X509TrustManager() {
    @Override
    public void checkServerTrusted(X509Certificate[] chain, String authType)
            throws CertificateException {
        try {
            customTm.checkServerTrusted(chain, authType);
        } catch (CertificateException e) {
            defaultTm.checkServerTrusted(chain, authType);
        }
    }

    @Override
    public void checkClientTrusted(X509Certificate[] chain, String authType)
            throws CertificateException {
        defaultTm.checkClientTrusted(chain, authType);
    }

    @Override
    public X509Certificate[] getAcceptedIssuers() {
        X509Certificate[] customIssuers = customTm.getAcceptedIssuers();
        X509Certificate[] defaultIssuers = defaultTm.getAcceptedIssuers();

        X509Certificate[] all = new X509Certificate[customIssuers.length + defaultIssuers.length];
        System.arraycopy(customIssuers, 0, all, 0, customIssuers.length);
        System.arraycopy(defaultIssuers, 0, all, customIssuers.length, defaultIssuers.length);
        return all;
    }
};

🔹 Étape 3 — Créer un SSLContext

Java
SSLContext sslContext = SSLContext.getInstance("TLS");
sslContext.init(null, new TrustManager[]{combinedTm}, new SecureRandom());

🔹 Étape 4 — Utiliser UNIQUEMENT pour ton appel REST

Exemple avec HttpClient (Java 11+)

Java
HttpClient client = HttpClient.newBuilder()
    .sslContext(sslContext)
    .build();
